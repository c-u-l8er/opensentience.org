Front matter, at the back

Reference

What the words mean, what the labels are derived from, and every file these pages name — with the ones you cannot open marked as such.

Definitions

Words this book uses in a particular way, and the acronyms it does not spell out every time. Each one says where its definition actually lives; none of them is defined here for the first time.

WRL WallRiderLang

an executable topology language whose meaning is a hash

Every board in this book is a WRL world: objects, the wires between them, and a semantic id that changes when the meaning does and not when a comment does.

Defined at WRL/README.md

TRVM term-rewriting virtual machine

a term-rewriting virtual machine on the interaction calculus — the model of computation where every step is a local graph rewrite and the result is provably independent of the schedule

TRVM's forge is what reduces a sealed WRL world into the Film you can step through. When a page says a world was 'reduced by the forge', this is what ran. Its README describes the same machine from the other side: a coordination-free distributed interaction-calculus runtime.

Defined at TRVM/site/index.html · published at trvm.traaviis.com

forge

the part of TRVM that reduces a sealed world epoch by epoch and emits a Film

It is the reason a board can be replayed rather than animated: the frames are a reduction's output, not scene data someone drew.

Defined at TRVM/forge/film.py

Film

the forge's own record of one epoch — one line per object, every field named

The boards in this book colour what a Film says changed. Hover an object and the readout shows that object's line, split into what it is doing now and how it was built.

Defined at TRVM/forge/film.py

FPLA Floor Programmable Locus Array

a locus-array direction of Travis's own, named in the foundation lane

It appears here only as one of the systems a pattern would apply to, never as evidence for one.

Defined at FPLA/README.md

BEAM

the Erlang virtual machine

Cited as prior art: it already satisfies some of what a pattern asks for, within one node. Saying so is what keeps a pattern from claiming novelty it does not have.

Prior art, outside this tree — the Erlang/OTP runtime system.

PX13

the hostname of the machine the recorded runs happened on

It appears in every execution identity. It is there so a run is attributable to a machine and a moment, not so the name means anything by itself.

Defined at _patterns/receipts

MOCK

a stand-in that does not measure anything

Marked in the open so it cannot be read as a measured log. A mock is never evidence, and a page that carries one says so at its limit.

Defined at ACADEMY.md

locus

the book's word for an active thing — the unit a pattern is about

It is defined by the book rather than borrowed, and the definition carries no evidence rung of its own.

Defined at AGENCY.md

The evidence labels

Every chapter carries a label, and no author types one: the build derives each from the record and refuses a record that tries to write its own. These are the rules it applies, read out of the build's own source when this page was made — so what you read here is what ran.

labelthe build derives it as
CHECKABLEwitness present ∧ evidence_kind ∈ the ledger's own vocabulary
RUNNABLEwitness.shape ∈ {suite, side-effect, lint}
EXECUTEDa receipt exists for the SAME bytes (sha256) with exit 0 — or the witness IS a receipt document
WITNESSEDkind == pattern ∧ EXECUTED ∧ rung ≥ in_tree ∧ every cited claim ∈ {PROVED, KNOWN, MEASURED, CONDITIONAL}
STAGEDwitness.staged ∧ the staged copy is byte-identical to the source (the site's own rule, run.js:6)
labelnull for definitions/anti-patterns · WITNESSED · STATED · PROPOSED (plan §1.2)

Parsed from opensentience.org/_patterns/build/build.mjs at build time.

The rung ladder

How close a witness is to having actually run somewhere a reader could check. A record may not claim a rung above the one the build can derive for it.

spec < in_tree < live_local < live_deployed < external

The three-valued outcome

The three-valued outcome vocabulary, used where a two-valued one would lie.

APPLIED
The work was done, and that is established.
REFUSED
The work was not done, deliberately, and the reason is published. A refusal is a result.
INDETERMINATE
Whether the work was done is not established. A timeout abandons a request but not the work under it, so 'no answer' is not 'no effect'.

Vocabulary from computedriven/receipts/R7-EXECUTED.md.

Questions

What is this book claiming?
That each chapter names one invariant, and that the label under it says exactly how much of it is established. Nothing on a page is stronger than its label. A chapter labelled STATED is a claim the book has not yet witnessed, and it says so on its own face.
Why does a chapter say STATED when the writing sounds confident?
Because the label is derived, not written. The build computes it from whether a check exists, whether a recorded run of that check exists for those exact bytes, and whether every claim the page cites is standing. An author cannot type a label in, and the build refuses a record that tries.
What makes a board different from a diagram?
A diagram is drawn. A board is a sealed WRL world reduced by TRVM's forge, and the frames you step through are that reduction's output. The geometry is computed from the graph, and the colours come from the Film.
Why can I not open some of the files the book cites?
They live in a repository that is not published. The book still names the path and its hash, because a citation you cannot follow is better than no citation — but it will not pretend to link you somewhere you cannot go.
Why are some wires unlabelled?
A wire that runs a long trunk down the margin carries its kind in its stroke, which the legend names, and in the readout when you hover it. The text was removed where it would have floated in a margin attached to nothing.
What is the counterexample section for?
A pattern that cannot fail is not a pattern. Once a record is WITNESSED the build requires a shipped counterexample — the case where the invariant does not hold — and refuses the record without one.
Is anything here peer-reviewed?
No. The evidence is a recorded run of a named check on named bytes, on one machine. That is a lower bar than review and a higher one than assertion, and every page states which of the two it has.
What does 'the build refuses' mean?
The build exits non-zero and emits nothing. It is not a warning that scrolls past: if a cited claim has been refuted, or a path does not resolve, or a count was typed by hand, the site does not get built at all.
